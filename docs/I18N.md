# Languages

English is the source of truth. Every other language (now: Portuguese, `pt`) is an
**overlay** that falls back to English wherever a string or file is missing, so a
course can be translated a chapter at a time. Reader's choice: Settings > Language
(synced with the account); `<html lang>` follows it.

## Where things live

| What | English | Translation |
|---|---|---|
| Interface text (buttons, settings, medals, tour) | `t('English text')` in `js/` | `i18n/<lang>.json`: English string -> translation |
| Lesson, exam | `courses/<id>/<file>` | `courses/<id>/<lang>/<file>` (full copy, same ids, same card order) |
| Trail texts | `courses/<id>/course.yaml` | `courses/<id>/<lang>/course.yaml`, an **overlay** (below) |
| Home list | `courses/catalog.yaml` | `courses/catalog.<lang>.yaml`, an overlay |
| Method, About | `pages/<id>.md` | `pages/<lang>/<id>.md` |

Overlays hold text only, so ids, kinds and files always come from English:

```yaml
# courses/<id>/pt/course.yaml
title: …
overview: { text: …, sources: [{ who: …, what: … }] }   # sources: same count and order as English
levels:  { ch01: { title: …, blurb: …, eyebrow: … } }    # by level id
lessons: { ch01-bubble: { title: …, summary: … } }       # by lesson id
```
```yaml
# courses/catalog.pt.yaml
title: …
tagline: …
courses: { <course-id>: { title: …, short: …, eyebrow: …, blurb: … } }
```

Progress is keyed by lesson and card ids, so it carries across languages.

## Interface strings (code)

`t('Text {n}', { n })`, `tn('{n} card', '{n} cards', n)` for plurals (both forms are
keys). The English string **is** the key, so never build one with `${}` and never
call `t()` at module top level (the language loads before the first render, not
before imports): use a function, or mark the string with `T('…')` (identity) and
look it up with `t(x)` when shown (medals, praise). Add every new string to
`i18n/pt.json`; `node tools/i18n.mjs ui` lists missing, unused and mismatched
`{placeholders}`. Brand name "Gibernoot Academy" is never translated.
Not yet translated: the labels inside widgets (`js/widgets/`: "Reset", "Play", …).

## Translating a course (a translation unit)

Order per chapter: build, audit, **then translate**; translate once the chapter's
lessons are final. Steps for each English file:

1. Write `courses/<id>/<lang>/<same path>`: same YAML structure, **every id, type,
   `correct:`, number, tile, answer, widget name and config unchanged**; translate
   only text fields (`title tag prompt body text feedback explanation hint steps label
   caption alt own name outro … rules debrief`, see `TEXT` in `tools/i18n.mjs`).
2. Math is frozen: every `$…$`, `$$…$$`, rune and `{{ }}` blank marker stays as in
   English, in the same order. Do not change a blank's text beyond translating the
   words outside math (editing a blank resets its recap progress).
3. Terms come from `courses/<id>/<lang>/GLOSSARY.md` (made once per course and language
   before the first file; read-only for translating agents). Names of people and works
   keep their usual Portuguese forms.
4. **Quotations** of published works use the established translation in that language
   when one exists; otherwise translate and keep the attribution. Never invent a
   quotation's wording.
5. Style is the project's: simple, flowing prose, no buzzwords, decimal comma in
   prose (never inside math), "você" form.
6. Run `node tools/i18n.mjs stamp <id>/<file>` right after writing a file (records the
   English file's hash), and `node tools/i18n.mjs check <id>` at the end.

`node tools/i18n.mjs status [course]` shows missing / stale (English changed after
the translation) / invalid / current files; `--list` names them. `check` compares
every translated file with English: same keys and array lengths, identical
non-text values, identical math, blank markers and link addresses; it warns when
most prose is still English. A stale file keeps working (it is shown as is) until
re-translated.

## Parallel translation

The main session makes the glossary, then runs at most **5 agents**, one chapter
level each, each writing only its own `<lang>/chNN/` files and running `stamp` and
`check` for them. Only the main session edits `STATUS.md`, runs validate and commits.
